# 🏢 Amazon ML Challenge 2026 — Business Entity Resolution

> **Task:** Match business entities from a master source (Source 1) against two noisy external databases (Source 2 & Source 3) across multiple countries.

---

## 📌 Problem Overview

Real-world business data is messy — company names are abbreviated differently across registries, addresses use varied formats, and legal suffixes (Inc., Ltd., SARL…) create noise. The goal of this challenge is to build a **scalable, accurate entity resolution pipeline** that:

- Identifies which records in Source 2 and Source 3 refer to the **same real-world business** as a record in Source 1.
- Handles **millions of records** efficiently using smart blocking strategies.
- Is evaluated using **Macro-averaged F₀.₅ score** (precision-heavy).

## ⚙️ Pipeline Architecture

The solution follows a classic **two-stage** entity resolution architecture:

```
Source 1  ──┐
             ├──► [1. Preprocessor] ──► [2. Blocker] ──► [3. Matcher] ──► Output TSVs
Source 2/3 ──┘
```

### Stage 1 — Preprocessing (`preprocessor.py`)
- **Unicode normalization** (NFKD) for consistent character encoding.
- **Lowercasing** and removal of special punctuation.
- **Legal suffix expansion:** `Inc → Incorporated`, `Ltd → Limited`, `Corp → Corporation`, etc.
- **Address abbreviation expansion:** `St → Street`, `Blvd → Boulevard`, `Ave → Avenue`, etc.

### Stage 2 — Blocking (`blocking.py`)
Prevents the O(n²) exhaustive comparison problem by generating a **pruned candidate set** per Source 1 entity using an **Inverted Index**:
- **Country-scoped indexing** — only entities from the same country are compared.
- **Prefix blocking keys** (`w1:`, `w2:`, `w12:`) for the top significant tokens.
- **Character 3-gram keys** (`ng:`) for typo-resilient matching.
- Candidates are **ranked by key overlap count**, with token keys weighted 3× over n-gram keys.
- Top-K candidates (`--max-candidates`, default: **25**) are passed to the matcher.

### Stage 3 — Similarity Scoring (`matching.py`)
Each candidate pair is scored using a **weighted combination**:

| Component | Method (RapidFuzz) | Method (Fallback) | Weight |
|---|---|---|---|
| Name — Token Set Ratio | `fuzz.token_set_ratio` | Token Jaccard | 50% |
| Name — Token Sort Ratio | `fuzz.token_sort_ratio` | — | 30% |
| Name — Character Ratio | `fuzz.ratio` | Levenshtein | 20% |
| Address Overlap | Jaccard on address tokens | Jaccard | 30% of final |

- If **both** name and address are present: `final = 0.70 × name_score + 0.30 × address_score`
- If address is **missing** in either record: `final = name_score × 0.95` (slight penalty)
- Pairs with `final_score ≥ threshold` (default: **0.75**) are declared matches.

### Evaluation (`evaluate.py`)
Implements the official **Macro-averaged F₀.₅** metric:

```
F_0.5 = (1.25 * Precision * Recall) / (0.25 * Precision + Recall)
```

- **Singletons** (Source 1 entities with no true matches): Score **1.0** if correctly predicted as unmatched, **0.0** otherwise.
- **Non-singletons**: Standard Precision/Recall/F₀.₅ per entity, then macro-averaged.

## 🚀 Quick Start

### 1. Clone the repository
```bash
git clone https://github.com/<your-username>/amazon-ml-challenge-2026.git
cd amazon-ml-challenge-2026
```

### 2. Download the dataset
Download the dataset ZIP from the Amazon ML Challenge portal and place it as:
```
Amazon ML Challenge/6ab10eb3b23ba_student_resource.zip
```
Then unzip it:
```bash
unzip 6ab10eb3b23ba_student_resource.zip
```

### 3. Install dependencies
```bash
pip install -r code/business_entity_resolution/requirements.txt
```

### 4. Run the pipeline on test data
```bash
python code/business_entity_resolution/src/pipeline.py \
    --s1 6ab10eb3b23ba_student_resource/student_resource/dataset/test/test_source1.tsv \
    --s2 6ab10eb3b23ba_student_resource/student_resource/dataset/test/test_source2.tsv \
    --s3 6ab10eb3b23ba_student_resource/student_resource/dataset/test/test_source3.tsv \
    --output-dir output \
    --threshold 0.75
```

### 5. (Optional) Evaluate on training data
```bash
python code/business_entity_resolution/src/pipeline.py \
    --s1 6ab10eb3b23ba_student_resource/student_resource/dataset/train/train_source1.tsv \
    --s2 6ab10eb3b23ba_student_resource/student_resource/dataset/train/train_source2.tsv \
    --s3 6ab10eb3b23ba_student_resource/student_resource/dataset/train/train_source3.tsv \
    --gt  6ab10eb3b23ba_student_resource/student_resource/dataset/train/train_ground_truth.tsv \
    --output-dir output \
    --threshold 0.75
```

### 6. Validate before submission
```bash
python 6ab10eb3b23ba_student_resource/student_resource/utils/validate_submission.py \
    --matching output/matching_results.tsv \
    --candidate output/candidate_pairs.tsv \
    --test-dir 6ab10eb3b23ba_student_resource/student_resource/dataset/test
```

## 🔧 CLI Arguments

| Argument | Default | Description |
|---|---|---|
| `--s1` | required | Path to Source 1 TSV file |
| `--s2` | required | Path to Source 2 TSV file |
| `--s3` | required | Path to Source 3 TSV file |
| `--gt` | `None` | Path to Ground Truth TSV (enables local evaluation) |
| `--output-dir` | `output` | Directory to write result TSVs |
| `--threshold` | `0.75` | Similarity score cutoff for declaring a match |
| `--max-candidates` | `25` | Max candidates per Source 1 entity from blocking |
| `--sample-limit` | `None` | Limit Source 1 rows (useful for quick testing) |

**Quick test run (first 500 rows):**
```bash
python code/business_entity_resolution/src/pipeline.py \
    --s1 ... --s2 ... --s3 ... \
    --sample-limit 500 --threshold 0.75
```
